# ADR 0006: Binary write-ahead log

- Status: accepted
- Date: 2026-09-27
- Phase: 2

## Context

Phase 2D is the redo log the disk engine will sync before it acknowledges a commit. The roadmap fixes the outline: physical-logical records (`PageWrite`, `TreeInsert`, `TreeDelete`, `TxnBegin`, `TxnCommit`, `TxnAbort`, `Checkpoint`), each with an LSN, a transaction id, a type, a length, a payload, and CRC32C; segment files `000000000001.wal`; a default segment size of 64 MiB; and group commit with a 1 ms window when several committers are waiting. It does not fix the byte layout, what an LSN counts, or how a torn tail differs from a bad checksum.

The page file already stores a checkpoint LSN and a per-page LSN as `uint64`. Zero means "never written" ([ADR 0004](0004-page-file.md)). The log is not applied in this phase. The shell still uses the text WAL in `internal/persist`. Wiring, checkpoints, and segment deletion are Phase 2E. Copying sealed segments to an archive directory is Phase 8.

`internal/wal` stays stdlib-only.

## Decision

**Format version 1, magic `GRWL`.** Each segment starts with a 28-byte header: magic, version, segment number, the LSN of its first record, and CRC32C of the bytes before the checksum. A newer version is refused from those first bytes before the checksum is checked. The record frame is little-endian: LSN, transaction id, type, payload length, payload, and CRC32C of the bytes before the checksum. The seven record types and their payloads are in [spec/wal.md](../spec/wal.md). An unknown type is rejected on append and reported as corruption if it is already on disk. Payload bytes are opaque to the frame, so a later phase can grow a commit payload without a new frame.

**An LSN is the record's start, and the first record is 1.** The value is 1 plus the number of record bytes before it. Segment headers are not counted. LSN 0 stays free for "no checkpoint" and "this page has never been logged." `Durable` is the first LSN not yet covered by a successful `Sync`. `Seek(0)` and `Seek(1)` both land on the first record.

**Append buffers. Sync fsyncs.** `Close` syncs first. A lone `Sync` does not wait. If other `Sync` calls are already queued, the leader waits the group-commit window (default 1 ms) and one fsync covers the batch. `Sync` returning nil means every `Append` that returned before that call is durable. `Sync` returning an error means those new records are not acknowledged; a prefix may still be on disk, and reopening is how the caller sees it.

**The last segment's torn tail is truncated. A complete record with a bad checksum is corruption.** On open, a short header, a header-only file whose checksum did not land, or a final record that runs past the file is a torn tail and is cut back to the previous record boundary. The reader never returns that partial record. A checksum mismatch on a record whose bytes are all present is `Corruption`, including when it is the last record, so a flipped bit is not discarded as a tear. The same defect in a segment that has a successor is corruption: that file was sealed and synced.

**A record is not split across segments.** When the next record would pass the segment size (default 64 MiB, including the header) and the segment already holds a record, the segment is synced, closed, and the record starts the next file. A record larger than the cap, when it is the first record in a segment, is written anyway and that file runs long. Segments are not deleted here. The checkpointer in Phase 2E does that.

**The archive hook runs after a segment is sealed and synced, before the next segment takes records.** `Archiver.Archive` must be idempotent and must not call back into the log. A hook error fails the `Sync`; the sealed file stays, and the next `Sync` calls the hook again. Open does not re-invoke the hook. A crash in that window is for Phase 8 to notice by scanning sealed segments.

## Alternatives considered

1. **LSN 0 for the first record, equal to a raw byte offset.** Recovery then cannot tell "no checkpoint" from "replay the first record" with a strict `record.LSN > page.LSN` test, because a fresh page is also 0. Starting at 1 keeps that comparison.
2. **Treat a bad checksum on the last record as a torn write.** That recovers more files after a crash that managed to write a full buffer of junk. It also hides a checksum failure of a record that was synced. Incomplete lengths are the tear. A full record that does not checksum is corruption.
3. **Always wait 1 ms before fsync.** That batches a single committer with itself and adds the window to every commit. The roadmap waits only when several committers are already waiting, which keeps a lone writer from paying the delay.
4. **Splitting a record across two segments.** The reader would have to join them, and a tear on the second half would look like a short record. Keeping a record inside one file makes the torn-tail rule a single offset.

## Consequences

- Phase 2E can open this log, append redo records, and `Sync` before acknowledging a commit. Page LSNs should be the WAL record LSN, which is never 0 for a real record.
- A crash after `Append` and before `Sync` loses that record. A crash during the write of a later record keeps every previously acknowledged record and does not surface a partial one.
- Sealed segments accumulate until Phase 2E truncates them. The archive hook does not copy them on its own.
- The shell and `internal/persist` are unchanged. The text WAL is still what the REPL replays.

## Follow-up

- Phase 2E orders this log ahead of page writes, replays from the checkpoint LSN, and deletes segments the checkpoint no longer needs.
- Phase 8 implements `Archiver` by copying sealed segments and uses that copy for point-in-time recovery.
- Phase 3 may put a write set in the `TxnCommit` payload. The frame already carries a length, so that does not bump the version.
